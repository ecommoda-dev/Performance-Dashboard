## 1. القرار اللي الشاشة بتدعمه

> **"كل جنيه دخل النظام راح فين؟"**

الصف الأول = **جسر بالقيمة**، وحدته **الجنيه** مش الأوردر. الأوردر الواحد ممكن
تتوزّع قيمته على أكتر من مربع — وده المقصود، مش خلل.

المعدلات بالعدد (نسبة RTO · معدل التسليم) → **صف تاني منفصل بصرياً**. ممنوع خلط
قيمة وعدد في نفس الصف.

---

## 2. المبدأ الحاكم

الحساب على مستوى **القطعة** مش الأوردر. لكل سطر:

```
Q = quantity                    (الكمية الأصلية)
C = currentQuantity             (الكمية الباقية)
P = discountedUnitPriceSet      (سعر القطعة)

راح  = (Q − C) × P
عاش  =  C × P
```

**هوية رياضية مضمونة:**
```
إجمالي القيمة = قيد التنفيذ + الفاقد + صافي المبيعات
```

## 3. المصادر الثلاثة

| السؤال | المصدر |
|---|---|
| القطعة نوعها إيه؟ (اتشالت · رجعت · بديلة) | **شوبيفاي** |
| الأوردر الأصلي اتسلّم؟ | **S1** = `Delivered` |
| دورة الإرجاع/الاستبدال خلصت فعلياً؟ | **S2** + `returns[].status` |

**السبب:** شوبيفاي بيعمل `Fulfilled` عند **الشحن** مش عند التسليم — فهو أعمى تماماً
بعد ما الأوردر يخرج من المخزن. S1/S2 هما المصدر الوحيد لما بعد الشحن.

## 4. قاعدة التصنيف الكاملة

### 4.1 الأوردر ملغي؟

```
cancelledAt ≠ null  +  displayFulfillmentStatus = UNFULFILLED  → كل القيمة → الفاقد ← ملغي
cancelledAt ≠ null  +  displayFulfillmentStatus = FULFILLED    → كل القيمة → الفاقد ← RTO
```

⚠️ ده يسبق أي فحص تاني. `manual_status` **مصدر ثانوي فقط** — ثبت إن Custom Flow كان
بيكتب `Cancelled` على أوردرات RTO.

### 4.2 تسوية دورات الإرجاع

```
دورة مُسوّاة  =  return.status = CLOSED
                  AND s2 ∈ { 'In-Return', 'Returned' }

CANCELED / DECLINED  →  تُتجاهل بالكامل
OPEN / REQUESTED     →  غير مُسوّاة — نتيجتها لا تُطبَّق
```

الشرطان مع بعض: `status` بيقول **أنهي دورة** (سجل دائم لكل دورة على حدة)، و S2 بيقول
**الوضع الفيزيائي** للدورة المفتوحة حالياً.

### 4.3 توزيع الجزء اللي راح — كمّي مش ثنائي

```
راح_الكلي     = Q − C
مرتجع_مُسوّى  = Σ returnLineItems.quantity  عبر الدورات المُسوّاة فقط
محذوف         = راح_الكلي − مرتجع_مُسوّى
```

لكل `returnLineItem` في دورة مُسوّاة:

| شرط الدورة | التصنيف |
|---|---|
| `exchangeLineItems` فاضي | الفاقد ← **مرتجع نهائي** |
| `exchangeLineItems` فيه سطور | الفاقد ← **مرتجع استبدال** |

الباقي (`محذوف`) → الفاقد ← **محذوف قبل الشحن**

⚠️ **السطر الواحد ممكن يكون في أكتر من دورة، وممكن يكون فيه تعديل ومرتجع مع بعض.**
الربط تراكمي بالكمية، مش واحد-لواحد.

### 4.4 توزيع الجزء اللي عاش

```
السطر بديل من دورة مُسوّاة    →  صافي المبيعات ← بديل
السطر بديل من دورة غير مُسوّاة →  قيد التنفيذ  ← بديل قيد التسليم
غير كده  →  s1 = 'Delivered' ?  صافي المبيعات  :  قيد التنفيذ
```

**السطر بديل** = `id` موجود في `returns[].exchangeLineItems[].lineItem.id`

## 5. المربعات

| # | المربع | المحتوى |
|---|---|---|
| 1 | **إجمالي القيمة** | `Σ (Q × P)` — الأساس 100% |
| 2 | **قيد التنفيذ** | تحت التأكيد · جاهز · مع المندوب · **بديل قيد التسليم** |
| 3 | **الفاقد** | ملغي · RTO · محذوف قبل الشحن · مرتجع نهائي · **مرتجع استبدال** |
| 4 | **صافي المبيعات** | مُسلَّم · **بديل** |

### قواعد عرض إلزامية

1. **"مرتجع استبدال" لا يُدمج مع "مرتجع نهائي".** الأول تبديل، التاني خسارة.
2. **مفيش أرقام سالبة.** نموذج القطعة ألغى الحاجة ليها.
3. **`subtotal` فقط.** الشحن مستبعد — تاب منفصل. `totalPriceSet` ممنوع (بيكبر برسوم
   الشحن المرتجع بعد التسليم).
4. **مؤشر حداثة** إلزامي مع عمر ملوّن.
5. **الاسم "إجمالي القيمة"** — مش "إجمالي المبيعات". الاستبدال بيضخّمه بقيمة البديل،
   والفرعي "مرتجع استبدال" بيفسّر المصدر.

## 9. تصحيحات إلزامية على المهارات

**تُطبَّق قبل أي محادثة بناء جديدة، وإلا هتشتغل بمعلومات قديمة.**

| المهارة | التصحيح |
|---|---|
| `ecommoda-order-lifecycle` | RTO يُحدَّد من `cancelledAt` + `displayFulfillmentStatus`، والميتافيلد ثانوي |
| `ecommoda-order-lifecycle` | ثغرة `s2_type` **محلولة من الـ API** عبر `exchangeLineItems` — لا حاجة لميتافيلد جديد |
